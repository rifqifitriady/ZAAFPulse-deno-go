# P4c M4 runs, 2026-11-13, MBA-ZAAF (Apple M4, 10 cores, 16 GB)

## After the root-cause fix (`1a62f2b`): the result files in this folder

The first runs (below, kept for the record; their files were committed in `b9b09c8` and are replaced here) stalled
for about a second in the front and go modes. Root cause: the front proxy's and the go engine's HTTP transports kept at
most 64 idle connections per host; streams that end together (the mock paces every stream alike) overflowed the pool,
those connections were closed, and the next wave dialled again: handshakes, TIME_WAIT and connect bursts past the listen
backlog (kern.ipc.somaxconn 128), whose SYN retries take about 1 s. Both now keep 1024 (`gw/front/front.go`,
`gw/engine/upstream.go`); regression tests `TestStreamWavesReuseProviderConnections` and
`TestForwardedWavesReuseUpstreamConnections` fail with 64 (236 new connections in a second wave of 300) and pass with
1024; the bench now fails a go step that opens more than 2 connections per worker to the provider. The gateway also runs
with a soft memory limit (`--mem-limit-mb`, config.json `gateway.memLimitMB`, default 64; a flag because the gateway's
environment is an allow-list, P4a E7).
