# P4f results: usage, audit events and trace spans over IPC (slice S8)

Date: 2026-11-17. Branch `migrate/p4f-ipc-events`, cut from `migrate/deno-go` at `ae7b9ab` (P4c), merged with
`migrate/deno-go` at `e41e2ea` (P4e) as `778ca7b`. Spec `docs/superpowers/specs/2026-11-16-p4f-ipc-events-design.md`
(D1–D25), plan `docs/superpowers/plans/2026-11-16-p4f-ipc-events.md` (its "Plan deviations found while building" list
every change from the plan).

## What ships

- **Trace spans from the go engine (D1–D8, D11).** For every request the engine answers (a served call, a stream, its
  own 429, a budget or guardrail refusal) it builds the SERVER span `POST /v1/chat/completions` and, per usage line, the
  CLIENT span `chat {model}`, byte-equal to what `lib/otel.js` stores for the same request (61 fixtures generated from the
  real `lib/otel.js`, `scripts/fixtures/gen-spans.js`, identical on Node and Deno). The usage line names its trace
  (`traceId`) under JS's rule. `config.push.trace.spans` tells the engine whether a span is recorded anywhere.
- **The control plane stores and exports them as JS would (D9, D11, D25).** A span is stored only while the trace
  store is on (otherwise skipped and still acknowledged, never a restart loop), written in batches before each ack, and
  exported through OTLP (`otel.exportRecord`, lossless: the same encoded span as JS's export).
- **OTLP export no longer keeps go off (D10, D12):** go classes run with export on, except with `captureContent: true`
  (owner answer, 2026-11-16). The routing reads OTLP status fresh (n2 closed).
- **Audit (D13, D24):** a go-served chat call writes no audit entry, as in JS. A stale budget snapshot's alert window
  writes one governance entry `gateway.budget_unchecked` (calls, since) as the system (design rule 2, owner decision).
- **The crash gap is closed (D14, D15):** `calls.journal` next to the outbox; a gateway killed during a whole answer or a
  stream leaves exactly one usage line for it (status 599, "the gateway stopped before the call ended", cost 0; owner
  answer, 2026-11-16), never two.
- **One rate-limit window (D16):** each engine tells the other the requests it admits (`ratelimit.take`), and a new
  gateway starts with the window (`ratelimit.window`). IPC v1 has 17 schemas.
- P3/P4a minors closed: T6-2 (exactly one line after a restart), T1-c (prune during a replay), T2-f (the acker retries
  a failed mark write).

## The S8 proof

`test/s8-equality.test.js` runs one corpus (13 calls: whole, fresh root, unsampled, streams with and without usage, a
private provider, provider 4xx and 5xx, a claude-code client, a rate-limited key, a route hand-off, embeddings) through a
`js` server and a `go` server and diffs the usage log, the cost ledger, the governance chain, the MCP audit log, the
trace store and the OTLP export, after relabelling generated ids and replacing times (money at nano-USD). **The diff is
empty on Node and on Deno** (local runs on `c152177`; CI below). Not in the corpus, as recorded engine differences:
a provider refusing the connection (`ECONNREFUSED` from the engine, `fetch failed` from Node's fetch: P4b's per-runtime
network text), and the stored usage line's key order (every field and value equal).

## Found while building

1. **One trace-store write per span saturated the control plane** at 200–500 streams (a gateway restart at 200, 505 ms
   at 500): D25 writes them in batches before each ack.
2. **The shadow counted a call twice** once the window was shared (its own Take plus the server's note): it now looks.
3. **A synchronous `ratelimit.take` blocked calls** while the control plane did not read (P4e's hang tests): takes go
   through a queue.
4. **The journal is `calls.journal`**: the outbox reads any `*.jsonl` as a segment.
5. **A refusal's shadow capture can come late on Deno** (CI: a rateLimit diff with the server's status 0): the shadow
   asks again before it posts its line.
6. The local ~15-minute stalls were the machine sleeping; long local runs use `caffeinate`.

## Known deviations from the JS gateway (pinned by Go tests, out of the corpus)

1. A response id that is not a string: JS loses the client span (a TypeError in `finishModelSpan`); the engine keeps it.
2. Gemini `finishReason` lower-casing: JS's full Unicode special casing, Go's `strings.ToLower`.
3. A chunk the engine's parser refuses (escaped lone surrogate, nesting > 512): JS reads its id and reasons.
4. An OTLP header secret inside a provider's error text is masked by JS's own secret list only.
5. `url.path` is the raw path (equal for every path the engine serves).
6. A string cut in a surrogate pair at 256/8192 units: JS keeps a lone high surrogate, the engine drops the pair.
7. A preset named like an `Object.prototype` member now gives its own name in JS too (a JS fix, not a difference).
