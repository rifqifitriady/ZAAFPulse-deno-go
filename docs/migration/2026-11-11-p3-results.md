# P3 results: the IPC contract between the Deno control plane and the Go gateway

Branch `migrate/p3-ipc-contract`, written 2026-11-11. Spec `docs/superpowers/specs/2026-11-11-p3-ipc-contract-design.md`,
plan `docs/superpowers/plans/2026-11-11-p3-ipc-contract.md`. Gate P3 of the program plan
(`docs/migration/2026-11-10-deno-go-migration-plan.md` §5).

## 1. Summary

- The v1 contract is frozen in [`ipc/v1`](../../ipc/v1/README.md): 14 message types, one JSON Schema each, plus the
  envelope schema (15 `*.schema.json` files in all). The additive-only rule is written in `ipc/v1/README.md`: inside v1
  only a new optional field or a new message type is allowed; anything else is v2.
- The transport is the gateway's stdin and stdout, one JSON message per line (corrected from a socket in the program
  plan, spec D1). There is no port and no token: only the parent holds the pipes, and the gateway exits when its stdin
  closes. The transport sits behind one interface on both sides.
- Both sides pass the same fixtures: JavaScript (`lib/ipc`, under Node and Deno) and Go (`gw/ipc`, standard library
  only). The Go process, `zaafpulse-gw`, is a protocol stub with a durable outbox; it serves no HTTP.
- `server.js` does not start the gateway, and no product behaviour changed. The plan said no product module is
  modified; by owner decision (option B of the final review) three writers carry one additive, opt-in parameter each:
  `lib/audit.js` `record(entry, opts)`, `lib/gateway/store.js` `jsonlLog.append(entry, opts)` and
  `lib/gateway/usage.js` `record(e, opts)`, which passes `opts` on to `jsonlLog.append`. Only `{ strict: true }` changes
  anything: a failed append then throws instead of being swallowed, which the IPC ingest needs so that it never
  acknowledges an unstored event. Without it (no second argument, `undefined` or `null`) every writer takes exactly its
  old path; no product caller passes a second argument, and the server's two `usage.record` wrappers drop one anyway.
  `lib/trace/store.js` is unchanged (`git diff aa78352 -- lib/trace/store.js` is empty): when its `writeSpans` throws
  because the index scan failed after a completed append, the IPC ingest looks for the span's `ipc` mark in the tail of
  the newest trace segment and treats it as stored when it is there (`lib/ipc/marks.js` `spanInNewestSegment`); the
  product's trace recorder still counts those spans as dropped and logs "traces: write failed", as before.
  `git diff --stat aa78352 -- server.js lib/gateway lib/cost lib/governance lib/audit.js lib/trace` therefore prints
  three files (`lib/audit.js`, `lib/gateway/store.js`, `lib/gateway/usage.js`; 14 insertions, 8 deletions);
  `server.js`, `lib/cost`, `lib/governance` and `lib/trace` are unchanged.

## 3. Measured latency

`bench/ipc-latency.js` (one run per runtime, 2026-11-11, one after the other, nothing else started by me). The
commands:

```bash
node bench/ipc-latency.js [--count 2000] [--events 30000]
deno run -q --no-prompt --allow-read --allow-write --allow-run --allow-env bench/ipc-latency.js [--count 2000] [--events 30000]
```

- Machine: MacBook with Apple M4, 10 cores, 16 GiB, macOS 26.6.2 (darwin-arm64). **On battery** (96 %, discharging),
  not on power as the plan asked, and not on a quiet machine: other apps were open.
- Go 1.27.3 (stub built by the bench), Node 24.16.0, Deno 2.9.8.
- Round trip: a `budget.snapshot` sent, the `health` the stub answers with (`--health-on-snapshot`) received, one at a
  time, 100 warm-up round trips not counted. Throughput: the stub emits 30,000 events (usage, audit, span) with no pause,
  from `ready` until the last one is stored by the real writers, acks included.

Raw output, one line per runtime:

```
{"runtime":"node 24.16.0","host":"darwin-arm64","roundTrip":{"count":2000,"p50Ms":0.043,"p95Ms":0.09,"p99Ms":0.12},"throughput":{"events":30000,"seconds":1.241,"eventsPerSecond":24173}}
{"runtime":"deno 2.9.8","host":"darwin-arm64","roundTrip":{"count":2000,"p50Ms":0.044,"p95Ms":0.097,"p99Ms":0.148},"throughput":{"events":30000,"seconds":2.401,"eventsPerSecond":12497}}
```

| Runtime | Round trip p50 | p95 | p99 | Throughput |
|---|---|---|---|---|
| Node 24.16.0 | 0.043 ms | 0.09 ms | 0.12 ms | 24,173 events/s (30,000 in 1.241 s) |
| Deno 2.9.8 | 0.044 ms | 0.097 ms | 0.148 ms | 12,497 events/s (30,000 in 2.401 s) |

Against M3 (the gateway's overhead budget is ≤ 5 ms p95): the IPC round trip p95 (0.09 and 0.097 ms) is about 55x
below it, and P4 sends a usage report per call, not a round trip. The event rate is far above any call rate the
gateway sees. One run per runtime on a busy machine: the numbers show the order of magnitude only, not a ranking of
Node against Deno (a later, smaller run by the Task 7 reviewer gave the opposite order).

Bench limits: each wait has a timeout (5 s per round trip, at least 60 s for the event stream), so a lost reply ends
the run with an error and the stub is killed; the 100 ms pause after `ready` assumes the reply to the handshake's
snapshot has arrived (on a stalled machine one late `health` would shift the samples by one); events that arrive in
the same read as `ready` are stored before the throughput clock starts (under 1 % of 30,000).

## 4. Kill tests

`test/ipc-kill.test.js`, with `test/fixtures/ipc/cp-child.js`, two tests per run of the file:

- **Gateway killed**: 20 runs. Each run starts the stub with `--emit 40 --emit-every-ms 1` (120 events), SIGKILLs it
  (`taskkill /F /T` on Windows) at a random point and restarts it until the control plane holds all 120. Every run
  kills at least once by construction; one assertion over all 20 runs requires at least one kill in mid-stream
  (0 < stored < 120).
- **Control plane killed**: 5 runs. The control plane is a child process under the same runtime (`cp-child.js`); it is
  SIGKILLed when a seeded number of usage lines is stored (plus 0 to 29 ms of jitter) and restarted until done. The
  test asserts `totalKills > 0`, so it cannot pass without killing anything.
- After every run: each usage line is stored exactly once, in order (no loss, no duplicate); the governance chain
  verifies; the MCP audit log and the trace store hold each event once; the outbox is empty. The ledger input
  (`gateway-usage.jsonl`) is checked by `seq`, not line body (see the known minors).
- Seeded: `ZP_KILL_SEED=<n>` names the kill points of a test in every name and failure message. A seed replays the
  kill points in the same order, not the interleaving (how far the stub got when it was killed depends on timing).

Where it runs: the Node `test` job on four OS (ubuntu, macos, windows-latest, `windows-11-arm`, where the hard kill is
`taskkill /F /T`), and the Deno `deno` job on Ubuntu and macOS. Outcome:

- Full-matrix run 43039341557 (`workflow_dispatch`, head `b954107`, 2026-11-11): all 17 jobs green, including
  `test (windows-latest)`, `test (windows-11-arm)`, `go (windows-latest)` and `go (windows-11-arm)`, every `go` and
  `test` job on the four OS, and `deno (ubuntu-latest)` and `deno (macos-latest)`.
- Push run 43039329191 (same head, Ubuntu only by the CI scope rule): all jobs green.
- Full-matrix run 43048746223 (`workflow_dispatch`, head `4627057`, the final fix round, 2026-11-11): all 17 jobs
  green (Node and Go on the four OS, Deno on Ubuntu and macOS, typecheck, `build-deno` on six targets).
- The CI evidence is these manual full-matrix runs (`workflow_dispatch`), not a pull request run: there is no pull
  request yet. The pull request's run will be added here when it exists. The per-run outcomes of the 20 + 5
  runs are pass/fail by job, not individual logs.

Defects the kill tests found, and their fixes:

1. **Order of `stream.json` and segment deletion** (found while the plan was written, Task 4 Step 2). A kill between
   deleting an acknowledged segment and writing `stream.json` could leave a `next` behind events already sent, so a
   reopened outbox reused their `seq` and the control plane dropped the new events as duplicates (about 1 run in 30).
   `Ack` now writes `stream.json` before it deletes a segment.
2. **An empty newest segment** (a kill between creating a segment and writing to it). `OpenOutbox` removes it before it
   reads the next `seq`.
3. Found later, during the tasks: a torn outbox write is truncated back (Task 4 fix round); on Windows the outbox
   writes without `O_APPEND`, truncating and seeking (`gw/ipc/outbox.go`, Task 6 fix round 1); the test fixture
   `cp-child.js` now waits for the last resent event before it shuts the stub down (a race in the test, not the
   product); the session test waits for the gateway's refusal line because the `exit` event can come before the last
   stderr line is read.

## 5. Spec deviations and open points

### Resolutions and corrections at the top of the plan (one line each)

Spec ambiguities resolved:

1. `refusePrefix` in `budget.snapshot` is left out (the refusal text is derivable); it can be added as an optional field.
2. `seq` gateway → control plane has two spaces: events carry the durable outbox `seq` of their stream, control
   messages count per connection from 1.
3. A stale snapshot (`now - at > 5000`) or none: the call passes with `budget: "unchecked"`, except that a blocking
   budget the snapshot shows as `exceeded` is always refused.
4. `trace.span` carries the stored compact record (hex ids), not the recorder's BigInt input.
5. `audit.event` with `log: "mcp"` carries the MCP audit entry, not an `AuditEvent` (a `oneOf` keyed by `log`).
6. `config.push`: `gateway` has no `keys` and no `apiKey` references; prices are Money; key `budgetUSD` and
   `BudgetView` amounts stay float USD.
7. The validator subset adds `pattern`, `minLength` and `minItems`, and reports any other keyword.
8. In Go a field without `omitzero` is required; a required pointer is the nullable one; one reflective `checkShape`
   enforces presence, null and the `ipc:"..."` rules.
9. The outbox is `DIR/.data/gw-outbox/` (or `--outbox <dir>`); `stream.json` holds `{stream, next, acked}`; a cut
   last line is truncated on open.
10. The budget decision's model is already normalized (`normalizeModel` stays in JavaScript until P4).
11. The "dashboard alert" in P3 is the supervisor's counter, its `status().alert` flag and a log line per minute.
12. Writer failures: the ingest calls the same writers as the in-process gateway, but strictly: `usage.record` and
    the MCP audit `record` with `{ strict: true }` (a failed append throws), and a `null` from the governance chain's
    `record` counts as a failure. A failure blocks the ack (the session kills the gateway, the supervisor restarts it,
    the replay stores the event once). A trace store that throws after its append completed is told apart by the
    span's mark in the newest segment. A write the in-process writers swallow is therefore no longer lost silently on
    the IPC path.
13. `runScope` and the gateway binary stay for P4 S1.

Where the spec was wrong or not feasible:

1. Tail recovery is bounded: the control plane reads the last 4 MiB of each store for `ipc` marks.
2. The compiled binary does not carry `ipc/`.
3. Message latency over the pipe needs a reply to time: a test-only `--health-on-snapshot` flag on the stub.

### P4 S1 entry conditions (must hold before `server.js` starts the gateway)

- **Outbox single writer (final review I1, with T4-2).** `OpenOutbox` takes no lock; exactly-once depends on the
  caller waiting for the old gateway to exit. Take an exclusive lock on the outbox for the gateway's lifetime, Go
  standard library only (`syscall.Flock` on Unix; on Windows `syscall.CreateFile` with share mode 0 on a lock file), and
  refuse to start (a distinct exit code, the supervisor backs off) while another process holds it. In the same change,
  treat "segments present, no `stream.json`" as damaged instead of starting a new stream (T4-2).
- **The server's writers do not carry the IPC guarantees (final review I2).** The ingest keeps strict sinks of its own,
  as `lib/ipc/local.js` does, or the server exposes strict, unwrapped equivalents. Three traps:
  - the server's `usage.record` wrappers (`lib/gateway/index.js:165`, `lib/otel.js:1664`) are `(e) =>` functions that
    drop the second argument, so `{ strict: true }` never arrives and a failed append is acknowledged; they also run the
    budget report themselves, so passing `afterUsage` as well double-reports the budget;
  - `govRecord` (`server.js`) sends some accounts' entries through the refusal limiter, which returns `null` when it
    drops one; the ingest reads `null` as a store failure and the gateway is restarted, over and over while that
    account stays over the limit;
  - the trace recorder (`lib/trace/recorder.js`) buffers spans and writes them later, so an acknowledged span would not
    yet be on disk.
- **The 4 MiB tail bound for `ipc` mark recovery (T4-7, with re-review R1): a mark file or a larger window.** A mark
  that falls out of the window is recovered too low. Since the gap check, that would refuse the gateway's next event
  forever (a restart loop); the session now raises the mark to the hello's `outboxFrom - 1` (`ingest.seed`), which
  closes the loop for acknowledged events, but the bound itself stays to be removed before P4 S1.
- **`deno compile` must include `ipc/v1` (T1-7).** `lib/ipc/schema.js` reads the schemas from disk; add
  `ipc/v1/*.schema.json` to the include list in `scripts/build-deno.js`.
- **Redact `Envelope.Body` before real secrets flow (T2-3).** The `secrets.handoff` body stays in the decoded
  envelope as raw JSON; zero it after decode (or redact it in every formatter) before the control plane sends real
  provider keys.

### P4 follow-ups

- Wire the supervisor into `server.js` behind `gateway.engine`, with the `runScope` grant for the binary and the
  dashboard alert (after the entry conditions above).
- The gateway inherits the control plane's whole `process.env` (`lib/ipc/session.js`): pass a minimal environment
  (`ZAAFPULSE_DATA`, `PATH`, and `SystemRoot`/`TEMP` on Windows), so provider keys in environment variables reach the
  gateway only through `secrets.handoff` (final review N-b).
- A refused handshake (exit 2) or a damaged outbox (exit 1) restarts forever every 30 s: stop and report
  `status().state = 'failed'` instead (final review N-c; fold in T3-3, the hello timer armed after a refusal).
- `reload()` while a session is starting is dropped and not re-sent once ready; the next restart picks up the new
  config, so it is bounded (final review N-d).
- Port `normalizeModel` with fixtures (the Go decision takes an already normalized model).
- A `config.json` to `config.push` converter (prices to Money).
- Keep every Go event send under one lock with the append and the replay (with T4-4), so the ingest's gap check never
  fires in normal operation.
- Settle the stub's exit code on a stdin read error (3 against the contract's 1, T3-5).
