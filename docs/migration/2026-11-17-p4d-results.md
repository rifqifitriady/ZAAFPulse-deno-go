## What ships

- **Eleven new sub-classes**, each with its own engine entry, shadow entry and switch-rule record (the owner's rule: 1
  clean day, 20 compares), default `js`: `messages`, `messages-stream`, `messages-count`, `responses`,
  `responses-stream`, `gemini`, `gemini-stream`, `gemini-count`, `embeddings`, `chat-anthropic`,
  `chat-anthropic-stream`. Suggested switch order (Decision 3): messages first (Claude Code), then chat-anthropic,
  responses (Codex), gemini, the two count sub-classes, embeddings.
- **Served by the go engine** when the sub-class is on go:
  - `/v1/messages` translated to any OpenAI-format provider, and passed through to a native Anthropic provider;
  - `/v1/responses` translated, and passed through to a native Responses provider;
  - Gemini `generateContent` and `streamGenerateContent` (a `provider%2Fmodel` path included: the front now classifies
    well-formed percent escapes), `countTokens` (the engine's own estimate);
  - `/v1/messages/count_tokens` (the estimate, or the native provider's count with a 15 s limit);
  - `/v1/embeddings`;
  - `/v1/chat/completions` to an Anthropic-format provider (callChat's translation both ways);
  - every one whole and streamed where the format streams; router presets (OpenRouter, Requesty, Portkey, Vercel AI,
    9router, LiteLLM) and Ollama/local providers as ordinary targets (private tier, the `reasoning_effort` soft drop,
    `x-zp-dropped`).
- **Guardrails** run on the form JS checks (the translated chat body; `{...body, model}` for passthroughs and
  embeddings; the picked fields for count_tokens, whose block answers the estimate), in the JS order: rate limit →
  price rule → budget → guardrails → provider. Refusals are written in the client's shape (OpenAI, Anthropic, Google).
- **P4f's hooks on every new path**: the call journal (a call that writes a usage line), the usage line through the
  outbox with its trace id, the server and client spans, the replicated rate window.
- **The shadow** compares every new sub-class: the control plane keeps the provider's answer as read, the client's
  head and bytes, the last usage line, and a tape of the random bytes and clock reads the translation drew; the engine
  replays the provider's text with that tape and compares (Anthropic pings removed: timing).
- **Kept on js** (hand-offs): `router/*` routes, the token saver when it would act (tool results), a model name only
  the model cache can map, `GET /v1/models` and `GET /v1beta/models`, OAuth2 and service-account providers (P4g),
  every refusal before the provider other than 429/402/guardrails (400 shape and translation errors, 403, 404, 413).

## Known differences from the JS gateway

1. A non-JSON 2xx from an Anthropic provider (or a JSON-typed answer to a stream request that does not parse): JS
   writes V8's `SyntaxError` text in the 599 line / error event, the engine its own text (Decision 26a).
2. A provider that cuts a translated stream: the error event's text is `terminated` (Node's); Deno's JS text differs
   (Decision 26b).
3. An SSE event over 16 MiB ends a translated stream with an error event; JS has no limit (Decision 26c).
4. A panic in a **translation step** (a port bug; none known) ends the call as JS's catch ends a TypeError (final review
   I3, re-review 2), and the call is metered: a translated stream's chunk or finish (an error event, the 200 line), a
   translated whole answer (the 200 line, the route's 502), the Anthropic leg's whole answer (the 599 line, the 502)
   and its stream conversion (no `[DONE]`, the 200 line), and a native passthrough's event reader (the 200 line with
   what was seen). Each is recovered, logged with its stack, and tested with an injected panic. The error text is Go's
   panic text, not V8's. **A panic elsewhere on the path is not recovered into a line**: in `deliverChatAnthropic`'s
   own loop, `RespondNative`, `deliverEmbeddings`, `TranslatedStream.Open`, `out.Error` inside a recover, or
   `tokensJSV`. Such a call ends with no usage line (its journal entry is `End`ed, the server span is written) and the
   panic goes on to net/http. JS has no such path; these are plain Go, not ports of JS semantics.
5. Native Responses passthrough (final review m4): an `error.message` that is a truthy non-string makes JS throw in
   `.slice` (no line, the route's 500); the engine writes `[object Object]` (or the number) and a line. A token count
   that is not a whole number is 0 in the engine (the IPC record holds integers); JS keeps it as it came.
6. Stream B's deviations 4, 5 and 8 apply (invalid UTF-8 inside `ReadSSE`, lone surrogates, non-V8 `TypeError` text).

## JS quirks copied (owner answer 31: fix in both engines after G3)

- A Gemini 502 is shaped `INVALID_ARGUMENT`.
- The embeddings line has no `error` on a non-2xx, and a thrown embeddings call writes no line.
- The Anthropic passthrough sets `requested` on every line; the Responses passthrough's 599 line keeps `requested` and
  `routedTo`, proxyChat's does not.
