# P4h: routes, cooldowns and provider quota readings on the Go engine — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The go engine serves route calls (`router/<name>`: fallback and round-robin, cooldowns from provider
headers) in every served class behind a `routes` switch, and the rotation counters, cooldowns and quota readings stay
one state across the two engines by replication both ways, proven byte for byte by fixtures from the real JS and by a
contract test of the cross-engine cooldown.

**Architecture:** A pure port of `providers.js`'s routing functions (`gw/engine/routes.go`) proven by function
fixtures; an engine-wide `RouteState` (outside the state generations) fed by local answers and by `provider.note` /
`route.take` control messages from the control plane, seeded by `route.state`; route plans that hold one single-target
leg per raw target, ordered in `Serve` after the take; `proxyChat`'s and `responsesPassthrough`'s fallback loops in
`serve_route.go`; the JS shadow capture gains the route tape and every line.

**Tech Stack:** Go (module `gw/`, `GOTOOLCHAIN=local`, standard library only). Node 24 and Deno 2.9 for generators and
the contract suite (CommonJS, `node:` built-ins only).

## Plan deviations

- Task 1: `Cooldown.Until` is a `float64`, not an `int64`. JS computes `until = now + max(1000, wait)` with a wait that
  is fractional for a fractional `retry-after` or reset (`"1.0005"` gives `until` 1767225601000.5 in `fn-note`), so
  `ipc.RouteCooldown.Until` (Task 2) must carry a JSON number that may be fractional.
- Task 1: JS `Number(string)` is `jsToNumber`; the name `jsNumber` is taken in `gw/engine/jsstr.go` (it is
  `Number.prototype.toString` there).
- Task 1: `NoteHeaders` keeps 13 names in all: readQuota's 12 (`x-ratelimit-{limit,remaining,reset}-{requests,tokens}`,
  `anthropic-ratelimit-{requests,tokens}-{limit,remaining,reset}`) and `retry-after`.
- Task 1: `Seed` and `Snapshot` take and give `ipc.RouteState`, which Task 2 adds; they are left to Task 2. Until then
  `Note` and `Take` send local `providerNote` and `routeTake` bodies of the same JSON shape (Task 2 swaps in the ipc
  types and constants).
- Task 1: an extra fixture `fn-readquota.json` covers readQuota and JS `Number()` on the limit and remaining values
  (hex, octal, binary, exponents, `Infinity`, `""`, `-0`, separators).
- Task 1: `jsDateParse` ports V8's `YYYY-MM-DD HH:mm[:ss[.f]]` variant for the years 0100-9999 with an optional `Z` or
  `±HH:mm` only; V8's legacy parser reads 0000-0099 as a guessed day, month and two-digit year, and accepts more zones
  and spacings (`+24:00`, ` GMT`, `+0700`): known differences under spec Decision 15a, kept out of the fixtures.
- Task 2: `RouteState` calls `send` with its mutex held, so provider.note and route.take leave in the order the state
  changed (strikes and rotations are order-sensitive); `send` must not block or call back. The gateway's `send` is a
  non-blocking enqueue on a 4096-message channel drained by one goroutine (a message that does not fit is dropped, as
  `ratelimit.take`). `RouteState.SetSend` sets it after `NewRouteState(nil)` in `engine.New`; `Engine.SetRouteSend`,
  `Engine.Routes` and `Engine.RouteControl(body any)` (a `*ipc.ProviderNote`, `*ipc.RouteTake` or `*ipc.RouteState`)
  are the engine's side. A remote take is applied only when this engine's route is a round-robin of more than one
  target, as `applyTake` in JS.
- Task 2: the note hook is `Upstream.SetOnAnswer(func(p *Plan, status int, h http.Header))`, run in `send` for the
  answer after the redirects (both answers of a 401 replay), so every class's provider call is noted, whatever the
  `routes` switch says.
- Task 2: `provider.note.status` is an integer 100-599; `route.state` is sent only when the supervisor has a `routes`
  source (server.js always gives one), so the existing handshake sequences without it are unchanged.
  `providers.routeState()` carries every cooldown entry, expired ones too (review I1; the Interfaces line said "live
  cooldowns only", which the spec's Decision 4 overrides): an expired entry keeps its strikes until a 2xx clears it, so a
  seeded gateway backs off from the same strikes as JS.
- Task 4: `Plan.Route` is `*ipc.RouteConfig` (the config type; there is no `ipc.GatewayRoute`). `State.target` is left as
  it is for the P4d planners (they still hand off `model: a route` until Task 5); chat finds the route with
  `State.routeOf`. The per-target helper is `chatLeg(r, body, key, t, model, save)`: it needs the client's model for the
  line and whether to scan for the token saver (a single-target call scans per leg as before; a route call scans the
  client body once). Shared route pieces: `routeLegs` (one leg per raw target, the `route: ` prefix on a leg's hand-off,
  `route: no usable target` for none) and `Plan.relegs`, with which `Save` builds the legs again from the shortened
  client body (spec Decision 9: every leg sends the shortened text, `savedTokens` only on the answer's line).
- Task 4: a token-saver hand-off of a route call at plan time keeps the saver's own reason (no `route: ` prefix), so it
  counts for the token-saver switch as before.
- Task 4: the journal is opened per leg (each 599 and fallback line closes its own entry); spans stay one server span
  and the answering leg's client span (the all-throw 502: the last 599 line's), as today's single-target call. Route
  spans for every line are Task 6.
- Task 4: until the route shadow compare (Task 7), a shadowed route call posts today's `model: a route` hand-off line.
- Task 4: an Anthropic leg's whole 2xx is converted inside the loop: a conversion that throws is a failed target (599
  line, next target), as callChat throws inside proxyChat's try.
- Task 4 review: the fallback-then-throw quirk answers 502 `upstream_error` (handle's catch over a TypeError), not
  500; `seq-chat-fallback-then-throw` and `seq-chat-saver` added. `RouteState.TakeOrder` takes and orders under one
  hold of the mutex (spec Decision 6). The translated paths (Task 5) should copy the same quirk: their `translated()`
  reads `r.text()` on a target that fell back too.
